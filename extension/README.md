# 求职自动化助手 · Chrome 扩展（半自动投递）

> 实习僧 / BOSS 直聘的**半自动投递执行层**。复用你已登录的浏览器，扩展自动填打招呼语、可选自动点投递，并把投递记录回写本地后端。

## 一、装扩展

1. Chrome 地址栏打开 `chrome://extensions/`
2. 右上角打开「开发者模式」
3. 点「加载已解压的扩展程序」，选本目录 `D:\Projects\job-hunter\extension`
4. 固定到工具栏，方便点开弹窗

## 二、前置条件

- 后端已跑：`cd D:\Projects\job-hunter && npm run dev`（后端 3100，负责接收投递记录回写）
- **已配置后端连接 + token**（见 §六；后端已做多用户隔离，不带 token 的回写会被 401 拒掉）
- 已在浏览器登录实习僧 / BOSS 直聘

## 三、使用流程（半自动，默认安全）

> v0.8.0 起弹窗只有三个页签：**投递 / 筛选 / 同步**。原来 5 个页签、三十多个平铺按钮，
> 日常真正会点的其实只有「开始、停止、同步」三个 —— 其余收进各自的「高级」折叠区。
> 折叠区里的按钮**逻辑一行没动**，只是不再占着首屏。

1. 打开实习僧 / BOSS 的岗位详情页（或搜索结果列表页）
2. 点扩展图标 → 「投递」页签
3. **打招呼语会自动从后端带出**（见 §七）：
   - 这条投递在网页端「AI 定制」生成过话术 → 用那条
   - 否则用网页「设置」里填的默认话术（`{{岗位}}` 已替换成当前岗位）
   - 想换一条点「重新取话术」；也可以直接在框里改（改了会覆盖本地，不再自动拉）
4. 选「投递范围」→ 点「开始」
   - **当前岗位**：只投你现在打开的这个岗位
   - **当前列表页**：投当前页上的若干家（数目＝「本轮每家」）
   - **双线并发**：实习僧 + BOSS 同时跑，两条线各自算额度
   - **一键（翻页/换词）**：自动翻页，一个关键词投完自动换下一个
5. 默认**不点投递**（半自动）：扩展只把话术填进沟通框，你检查无误后自己点「投递/沟通」
   - 勾「自动提交」才是全自动
6. 成功后自动回写一条「已投递」记录到网页端

回填投递进度（已读/被拒/初筛…）：切到「同步」页签，对着对应页面点一次
「同步（实习僧投递页）」或「同步（BOSS 聊天页）」。


## 四、安全策略（写死）

- **每日额度**：默认 50 份，硬上限 150，超出自动停止（弹窗可重置）
- **随机间隔**：自动点击模式下，点击前随机等待 4–10 秒，模拟真人手速
- **验证码/风控即停**：检测到滑块、安全验证、「沟通上限」等提示时立即停止，人工处理
- **不绕过验证码**：命中即停，绝不尝试破解
- **关键词黑名单**（M5 新增）：岗位/公司命中黑名单关键词（如「外包、驻场、销售岗」）即跳过，不消耗额度；弹窗可配置
- **BOSS 活跃度过滤**（M5 新增）：勾选「仅投活跃岗位」后，自动跳过「半年前活跃」等僵尸岗，只投近期活跃的 HR；不消耗额度

> 过滤与额度顺序：**过滤在额度检查之前**，被黑名单/活跃度拦截的岗位不会白扣每日额度。

## 五、校准选择器（重要）

`content.js` 里的选择器是**启发式**的（优先找 `textarea`、按「立即投递/沟通」等文本找按钮），
不同平台/版本可能对不上。校准方法：

1. 打开目标投递页 → 点弹窗「探测页面结构」
2. 展开「页面结构」，把 JSON 贴给 AI，AI 会锁定精确的输入框/按钮选择器并更新 `content.js`

## 五·五、投递进度同步（把平台状态抓回本地）

投完就不管的阶段结束了。现在可以把平台上的进度同步回来，网页端「投递漏斗」就能算出转化率。

**怎么用**：

1. 打开 **实习僧 → 我的投递 → 投递反馈**（或 BOSS 对话列表）
2. 扩展弹窗 →「记录」页 → **「投递进度同步」**
   - **「一键采集全阶段并上传」**：遍历 7 个分类 tab + 翻页 → 自动上传 → 显示汇总
   - **「全阶段采集（先看预览）」**：同上但只出预览，不自动传（想先确认抓对了用这个）
3. 预览按**阶段分组**列出（已投递 / 被查看 / 初筛 / …），并标出每条是按哪个 tab 判的
4. 回网页端 `/funnel` 看漏斗

**七档全采**：实习僧「投递反馈」把投递分在 7 个分类 tab 里
（已投递 / 被查看 / 初筛 / 笔试 / 面试 / 不合格 / 录用）。采集器会**逐个点开这些 tab、翻完每个 tab 的所有页**，
再按 jobId 合并成一条，**阶段取权重最大的那个** —— 和后端「只前进」用的是同一把尺子。
采完会把你原本停留的 tab 切回去。

> ⚠️ **镜像守卫**（`collectAllTabs` 里的核心判断，别删）：
> 真机上 7 个 pane 渲染的是**同一份全量列表**（每条都写「投递成功」）。
> 如果无条件拿 tab 名当阶段，就会把所有投递都标成「录用」。
> 所以规则是：**与「基线 tab（行最多的那个）」jobId 集合完全相同的 tab 判为镜像，
> 它的 tab 名不参与阶段判定，只信行内文案**。等某条投递真进了「初筛」，该 tab 的集合不再等于基线，
> 守卫自动失效、tab 名开始生效。

**为什么必须点 tab 而不是直接读隐藏 pane**：`innerText` 对不可渲染的元素会退化成 `textContent`，
卡片里各字段之间没有换行，整条投递会糊成一行，被「至少 2 行」的判据直接丢掉。真机验证过这个行为。

**怎么认「这一行」**：靠**岗位详情链接**，不靠 class、也不靠阶段词。
每条投递里恰好有一个 `/intern/inn_xxx`（BOSS 是 `/job_detail/xxx.html`），
从它向上找到「只装了自己一个岗位链接」的最大容器 —— 那必然是单条投递卡片，不会是整张列表。
`candidateRows()` 还会**跳过不可见的行**：7 个 tab 各有一份 DOM，不过滤的话翻页判断会把 7 份混在一起，永远判「列表没变」。

> ⚠️ 2026-11-02 真机事故：早期实现是「按阶段词向上找容器」，第一个命中的其实是**顶部分类 tab**
> （「已投递 被查看 初筛 笔试 面试 不合适 录用」这一整串），一路向上找到 `.el-tabs`，
> 于是整个页面被当成了「一行」：公司名抓成岗位名、岗位名抓成 tab 那串字，7 个阶段上报同一条记录。
> 现在除了改成链接驱动，解析层还留了一道硬过滤：**一行里出现 ≥3 个阶段词 = tab 标签串，整行丢掉**。

**行内状态写的是「投递成功」不是「已投递」**：实习僧列表里那一格就写「投递成功」，
它等同于「已投递」（stage=submitted，不会算推进）。而顶部 tab 才是平台对这条投递的最新归类，
所以规则是「行内文案和 tab 分类取权重更大的那个」—— 你在「初筛」tab 下看到的记录，
即使行内还写着旧的「投递成功」，也会按初筛记（这条只在 tab 不是镜像时成立，见上面的镜像守卫）。

**公司名会带城市**：平台写「法雷奥-深圳」，采集时会拆成 公司=法雷奥 / 城市=深圳。
不拆的话和后端已存的「法雷奥」对不上，同步结果会全是「忽略」。

**采集的三条边界**（写死在 `collector.js` 里）：

| 边界 | 原因 |
|---|---|
| 只点「分类 tab」和「下一页」，**绝不点投递 / 沟通 / 撤回 / 删除** | 前者只改「显示哪一页」，不改平台状态；后者会真的动你的账号 |
| 认不出就不上报 | 宁可漏一条，也不要把错的进度写进库 —— 脏数据比没数据更难发现 |
| 已读/已回复只记首次时间 | 重复同步不能把时间刷成今天，否则「平均多久被查看」永远等于最后同步时间 |

**BOSS 的「已回复」不推进漏斗阶段**：HR 回一句「方便发份简历吗」不代表进了初筛，
算成初筛会让漏斗第二层虚高。回复率是单独一个指标，在漏斗页第一排卡片里。

**BOSS 的「已读」不是文字，是图标 class**（v0.7.3）：页面上根本没有「已读」两个字，
只有气泡旁的 `<i class="message-status status-read">`（`status-delivery` = 已送达未读）。
所以按文本找阶段词在 BOSS 上永远 0 命中 —— 采集端要读 class，不是读文字。

**BOSS 会话列表的真结构**（v0.7.5 真机实测，`/web/geek/chat`）：

```
UL
└── LI（没有 class，可能带 data-*）
    └── DIV.friend-content        ← 一行会话，innerText 固定 4 段
        11月03日                  ← 时间
        秦女士KeepHR              ← 姓氏称谓 + 公司 + 角色（公司名只能从这里剥）
        [已读] / [送达]           ← <i class="message-status status-read|status-delivery">
        您好，我是计算机应用工程…   ← 最后一条消息（我方固定打招呼语 or 对方的回复）
```

三个必须记住的点：
- **列表里没有岗位名**：打招呼语是同一段固定文案，光看列表分不出投的哪个岗 → 只能点开会话
- **`read` 三态**：`status-read` = 对方已读 / `status-delivery` = 只送达 / **没有图标** = 多半是对方最后发的（≈ 已回复）
  （实测 19 条会话 = 6 已读 + 9 送达 + 4 无图标；用户回复过之后那 4 条会变，所以它不是稳定属性）
- **`li` 上没有任何 `id` / `data-*`**（v0.7.7 真机实测 `attrs: {}`）：拿不到加密 jobId，
  「只读列表就采集」这条路是堵死的

**右侧对话区在哪儿**（v0.7.9 真机，连探 3 次才对）：

```
DIV.chat-wrap
├── DIV.list-warp.v2        左栏（上面那个 UL 在这儿）
│   └── DIV.chat-user.v2
│       ├── DIV.boss-search-top
│       ├── DIV.label-list    ← 全部/未读/新招呼…（只有 16 字）
│       └── DIV.chat-content ← 只有 .user-list
└── DIV.chat-conversation   ← 对话区在这里，比列表高**两层**
```

⚠️ 两个坑：① 只找「列表直接父级的兄弟」永远找不到它（那里只有搜索框和标签栏）；
② 只按字数挑兄弟节点会把 `DIV.label-list` 当对话区（它是那层最长的）。判据是
`looksLikeChatPanel()`：≥60 字 **或** 里面有消息节点。

点开一条会话后（v0.7.11）：
- 岗位名 / 薪资 / 城市在 `DIV.chat-position-content`，`SPAN.salary` 单独放薪资
- 消息行是 `UL.im-list > LI.message-item`，**我方消息带 `[已读]/[送达]` 图标，对方不带**
- 「查看职位」是 button 不是 `<a>` → **仍然没有 jobId**，后端只能按「公司 + 岗位名」匹配
- 招聘者姓名/公司在 `.base-info` 里各占一个 `span`（分字段读，别拆文本）

**「采集会话（BOSS 聊天页）」按钮**（v0.7.12）：逐条**点开**左侧会话读岗位名 / 已读 / 对方是否回过话。
默认只点「已读」和「对方最后发言」的 —— 点开会把对方发来的未读标成已读（HR 那边看得到），
「我发了对方还没看」的那批点了纯浪费。点开但右栏没换内容时**整条跳过**，
绝不把上一条的岗位名记到这一条头上。采完仍然先看预览再上传。

**上传时后端会兜底「按岗位名认人」**（v0.7.15，服务端逻辑）：聊天页拿不到 jobId，
只能「公司 + 岗位名」匹配；而账本里那批一键投递的记录公司名是抓页面抓错的
（2026-11-05 A69277 事故：投的是正浩创新，账本记成 RAK瑞科慧联），公司这一半一旦对不上，
已读 / 被拒的时间一条也传不进去，界面看起来就「全都还是已投递」。
所以：`source=chat` 且没有 jobId 的条目，公司对不上时**再按岗位名认一次**，
命中就顺手把错的公司名订正掉（弹窗会列「订正 N 条公司名」）。
两条约束：① 岗位名在全库**唯一**才认（「测试实习生」这种重名的宁可 ignored，不能记到别人头上）；
② 拆文本猜出来的公司名（`companyGuess`）不拿来覆盖真实值。
另外 HR 主动找你、你一句话没发过的会话（`myMsgCount===0`）即使开了 `createMissing` 也不建记录 ——
那不是你的投递，建了会把「投递量」撑大。

**「探测（校准用）」在什么都认不出时会吐四段结构**（v0.7.3）：`layout`（全局重复块）、`containers`（子元素高度同构的列表容器，最像会话列表的就是它第一项）、
`signals`（`status-read` / `unread` / `[class*=chat-user]` 各多少个 + 首样本）、`frames`（iframe 数量与可访问性）。
⚠️ 以前只要页面里命中 1 个阶段词（哪怕是筛选栏的「未读」tab）就整段不输出，等于白跑一趟；现在无条件输出。

## 六、扩展 ↔ 后端通信

后端从「单人自用」升级为多用户后，所有 `/api` 都要求登录。扩展这边两件事都可配，**不用改代码**：

1. 打开扩展弹窗 → 「记录」页 → 最下面 **「后端连接（多用户后必须填 token）」**
2. 后端地址：默认 `http://localhost:3100`，换端口就改这里（manifest 已放开到 `http://localhost/*`，不用重新加载扩展）
3. 登录 token：网页端登录后，在**网页端**的控制台执行 `copy(localStorage.getItem('jh_token'))` 复制，粘进来
4. 点「保存并测试」→ 显示「✅ 已连接，当前账号：xxx」就算通了

原理：`content.js` 的 `backendBase()` / `authHeaders()` 从 `chrome.storage.local` 读 `jhBackend` / `jhToken`，
两个键名与 popup 里保存的必须一致。

**401 会怎样**：本地投递账本照记（不会重复投），但网页端不会出现这条投递记录，
content 控制台会打一行 `回写被拒（401）`。token 有效期 7 天，过期后重新复制一份即可。

> 为什么 token 不能硬编码进扩展：token 等同于账号密码，进 git 就等于把账号公开。
> 所以它只存在本机 `chrome.storage.local` 里。

## 七、批量投递（M6）

**前提**：开新一批要在**实习僧「搜索结果列表页」**（详情页抓不到链接）；BOSS 已经支持批量（走「立即沟通 → 发招呼语」，需要先在「单次投递」页填好招呼语）。

**流程**：
1. 列表页搜好关键词 → 点扩展 → 设「本批家数」（默认 10，上限 20）→ 点「批量投递本页岗位」
2. 扩展从列表页抓 `a[href*="/intern/inn_"]`，按岗位 id 去重，存成队列
3. 自动跳到第 1 家 → 页面加载后 content script 自己续跑：投递 → 记录 → 停 15–30s → 跳下一家
4. 弹窗里能看到「已执行 X/N（成功 Y）」和「下一家」，点「停止」立即叫停

**跨页进度**：存在 `chrome.storage.local` 的 `batch` 键里（页面一导航 content script 会重新注入，只有 storage 能跨页保留状态）。

**一键投递（v0.5.0 起支持多关键词轮换，v0.7.0 起支持多城市）**：

| 能力 | 说明 |
|---|---|
| 前置条件在插件里配 | 关键词 / 城市（可多选）/ 类型（实习、校招）；不用每次进网站点栏目、点城市 |
| 多个关键词 | 关键词框用逗号 / 顿号 / 换行隔开，最多 10 个。跑完一个词的**所有页**后自动跳到下一个词的搜索结果页，全部跑完才收工 |
| 多个城市（v0.7.0） | 城市是 chips 多选。**勾多个 = 跑多轮**，不是一个地址搜多个城市：实习僧的 `city` 是单值 query 参数。展开顺序是「城市在外层、关键词在内层」——先把深圳的几个词跑完，再跑广州，依次往下 |
| 自动翻页 | 靠改 URL 的 `page` 参数跳页，翻完自检「两页岗位集合是否相同」判断翻页到底成没成 |
| 一处都不动手 | 点一次「一键投递」后弹窗可直接关：跳页、开投、翻页、换词都由页面自己接管（弹窗会被浏览器销毁，不能靠它等待） |
| 各轮总账（v0.6.0） | 换一轮会把队列 / 结果清零，所以每轮跑完时单独记一行「翻了几页、投了几家、拦了几家」。弹窗显示「本轮明细」，一眼看出是哪一轮没量 |
| 英文岗名也认（v0.6.0） | 方向词表加了 `test engineer` / `quality assurance` / `sdet` / `test automation` 等；英文按**词边界**匹配（`test` 不会命中 `latest`），中文仍用包含 |

**多城市为什么必须展开成多轮**：`?city=深圳&city=广州` 这种写法实习僧只认第一个（Express 解析多值参数取数组，站点取标量）。所以界面上勾 2 城 × 4 词 = **8 个搜索任务**，串行跑完。代价是耗时翻倍，所以：

- 界面上多选时会直接写「已选 2 个：深圳、广州（**每城各跑一轮**）」，不让人误以为只搜一次；
- 从「筛选条件」兜底搬城市时**只取前 5 个**（筛选范围可以很宽，但每个城市都要真跑一轮，全搬过来会跑一整天）；
- 任务名统一显示成「城市·关键词」（`taskNameOf`），跑到第 5 个时不会以为同一个词跑了两遍。

**v0.6.0 修的两个「看着像插件坏了」的提示**（都来自 2026-11-05 真机：4 个关键词跑完，只剩最后一句看不懂的原因）：

- 翻到第 2 页空 → 以前报「当前页面没抓到岗位链接（新建一批要在搜索结果列表页启动）」，人在列表页上看到这句只会以为插件认错页；现在报「第 2 页没有岗位了（这个搜索条件只有 1 页，已经到底）」，且不再补一句同义的「已到页数上限」。

- 换词时 `blockedList` / `blockedTotal` 以前跟着旧批次一起 carry 到下个词，而新词第 1 页若 0 可投会走扫描分支做「旧数 + 本页数」→ 「被筛选拦掉 56 家」里混着上个词的数。现在换词即清零（这个词的账已进 `kwStats`）。
- 方向不符的原因以前念的是**方向标签**（`标题里没有「测试开发 / 软件测试、自动化测试 / SDET… 等 4 个」这类词`）—— 带斜杠的那串字在原文里根本不存在。现在念**真实关键词**，并且「例如」后面给的是**岗位标题**，方便判断是不是误杀。
- ⭐ **原因文案必须短到弹窗放得下**：弹窗内容宽只有 332px，原因那栏原来 `max-width:45%`（≈14 个 10px 字），套话「标题里没有你要的方向词」占掉 11 字后，真正想看的「插件找的是什么词」永远显示成 `「测…」`——**改成念真实关键词也没用，全被 CSS 切掉**。现在：① 原因**独占第二行**（标题一行、原因一行）；② 文案压到 33 字内（`标题和 JD 都无方向词（找「测试开发」「自动化测试」等4组）` = 31 字）；③ 单测里守住长度上限，写长了当场红。

## 七、打招呼语从哪来（v0.8.0）

BOSS 的「投递」＝发出这条消息，所以话术是投递的前置条件。以前只能手动粘进弹窗：
网页端「AI 定制」给每个岗位生成的那条，扩展根本拿不到，于是每次投递都要
「复制 → 切弹窗 → 粘贴」—— 话术越好用，这一步越烦。

现在弹窗打开时会自己调后端 `GET /api/greeting?company=&jobTitle=`：

| 顺序 | 来源 | 什么时候命中 |
|---|---|---|
| 1 | **这条投递自己的 `greeting`** | 网页端「AI 定制」为这个岗位生成过 |
| 2 | **默认话术**（网页「设置 → 默认打招呼语」） | 没定制过，兜底 |
| 3 | 空 | 两样都没有 → 提示「去网页设置填默认话术」 |

匹配用「公司 + 岗位名」（平台标题的「…实习招聘」尾巴会先剥掉）。
默认话术支持两个占位符 `{{公司}}` / `{{岗位}}`，**由后端替换好再返回** ——
扩展不拼字符串，就不存在两边替换规则不一致的问题。

⚠️ 本地框里已经有内容时**不会覆盖**（你可能自己改过），只想换一条就点「重新取话术」。
⚠️ 话术存后端而不是 `chrome.storage`：扩展是独立进程，而「设置里改一次、所有设备都用」
这个语义只有后端有。

## 八、v0.8.0 瘦身踩的坑：「确认上传」被收进了折叠区

为了把首屏按钮从 29 砍到 15，`确认上传` 和「探测 / 重置」一起被放进了
「高级 · 预览 / 校准 / 重置」。问题在于**两种同步的收尾方式不一样**：

| 入口 | 采完干什么 | 上传按钮在哪 |
|---|---|---|
| 同步（实习僧「我的投递」） | 采集 → **自动上传** | 不需要 |
| 同步（BOSS 聊天页） | 只出预览，**强制人工确认** | ← 就是这里，被藏起来了 |

结果是：采完 9 条会话、状态栏写着「确认无误再上传」、预览一切正常，
但主流程上没有任何上传入口 —— **数据一条也没进库，而且不留任何报错**。
（账本里那 10 条 BOSS 记录 `readAt` 全空、4 条公司名还是错的，就是这个状态。）

修法：`确认上传（N 条）` 移到预览正下方、跟预览同屏，采到东西才出现
（`hidden`，条数写进按钮文案），没东西就消失。上传成功后自动隐藏。

配套钉了一条回归：`scripts/test-popup-ids.mjs` 现在会扫描 `<details>` 嵌套深度，
**主流程按钮（开始/停止/两个同步/确认上传/刷新账本/标记已投/取话术）一旦被收进折叠区就判红**。
这条规则的价值在于：按钮藏起来不报错、界面照常、测试全绿，只有真机才发现数据没进去。

## 九、v0.8.2：「点了没反应」不是点不动，是点在了一个已经不在页面上的节点

真机 2026-11-05（扩展 0.8.1）：10 条里 9 条采到，**赵怡和/智传信那条被跳过**，
提示写着「点了没换内容」。查下来是两个原因叠加，都不报错：

| 原因 | 为什么 | 症状 |
|---|---|---|
| 左栏节点被重渲染换掉 | BOSS 左栏是 React 渲染的，**点开一条会清未读红点 → 整列重画**，而循环开头是一次性抓下来的 node 列表 | 对**游离节点** `el.click()` 不抛错也不跳转 → 白点一次 |
| `active` 类名认不出来 | 判断「本来就开着」只看 class 里有没有 `active`，站点换标记就失效 | 明明右栏就是这个人，却被当「点了没反应」丢掉 |

两条修法：

1. **点之前先验活**：`el.isConnected === false` 就按**行文本指纹**（招聘者 + 公司/岗位两行）
   重新找一遍，找到再点。⚠️ 用指纹不用下标 —— 重画后顺序可能变，按下标会点错人。
2. **失败后再验人**：指纹没变不代表点失败。给一次兜底：右栏读到的**招聘者名和公司名
   都必须出现在这一行的文本里**才算「本来就开着」。少一个条件都不行 ——
   否则就会把上一条会话的岗位记到这条头上，那比漏一条严重得多。
   （测试 ⑧ 和 ⑫ 就是这两条的镜像：⑧ 防错标，⑫ 防误丢。）

预览里会多一行提示：`N 条左栏被重渲染，按文本重定位后点开的`。
