# 求职自动化助手 · Chrome 扩展（半自动投递）

> 实习僧 / BOSS 直聘的**半自动投递执行层**。复用你已登录的浏览器，扩展自动填打招呼语、可选自动点投递，并把投递记录回写本地后端。

## 一、装扩展

1. Chrome 地址栏打开 `chrome://extensions/`
2. 右上角打开「开发者模式」
3. 点「加载已解压的扩展程序」，选本目录 `D:\Projects\job-hunter\extension`
4. 固定到工具栏，方便点开弹窗

## 二、前置条件

- 后端已跑：`cd D:\Projects\job-hunter && npm run dev`（后端 3100，负责接收投递记录回写）
- 已在浏览器登录实习僧 / BOSS 直聘

## 三、使用流程（半自动，默认安全）

1. 在网页端「投递追踪」里新建一条投递，粘贴 JD → 点「🤖 按 JD 定制」生成打招呼语
2. 复制打招呼语 → 打开实习僧某个岗位的投递页
3. 点扩展弹窗 → 粘贴打招呼语 → 点「投递当前岗位」
4. 扩展会自动填入沟通框；**默认不点投递**（半自动），你检查无误后自己点「投递/沟通」按钮
5. 成功后自动回写一条「已投递」记录到网页端

## 四、安全策略（写死）

- **每日额度**：默认 50 份，硬上限 150，超出自动停止（弹窗可重置）
- **随机间隔**：自动点击模式下，点击前随机等待 4–10 秒，模拟真人手速
- **验证码/风控即停**：检测到滑块、安全验证、「沟通上限」等提示时立即停止，人工处理
- **不绕过验证码**：命中即停，绝不尝试破解
- **关键词黑名单**（M5 新增）：岗位/公司命中黑名单关键词（如「外包、驻场、销售岗」）即跳过，不消耗额度；弹窗可配置
- **BOSS 活跃度过滤**（M5 新增）：勾选「仅投活跃岗位」后，自动跳过「半年前活跃」等僵尸岗，只投近期活跃的 HR；不消耗额度

> 过滤与额度顺序：**过滤在额度检查之前**，被黑名单/活跃度拦截的岗位不会白扣每日额度。

## 五、校准选择器（重要）

`content.js` 里的选择器是**启发式**的（优先找 `textarea`、按「立即投递/沟通」等文本找按钮），
不同平台/版本可能对不上。校准方法：

1. 打开目标投递页 → 点弹窗「探测页面结构」
2. 展开「页面结构」，把 JSON 贴给 AI，AI 会锁定精确的输入框/按钮选择器并更新 `content.js`

## 六、扩展 ↔ 后端通信

- 扩展 content script 通过 `fetch` 直接 POST `http://localhost:3100/api/applications` 回写投递记录
- 后端已开启 CORS，允许任意来源（仅本地自用）

## 七、批量投递（M6）

**前提**：在**实习僧「搜索结果列表页」**启动（详情页抓不到链接）。BOSS 暂不支持批量（沟通机制不同）。

**流程**：
1. 列表页搜好关键词 → 点扩展 → 设「本批家数」（默认 10，上限 20）→ 点「批量投递本页岗位」
2. 扩展从列表页抓 `a[href*="/intern/inn_"]`，按岗位 id 去重，存成队列
3. 自动跳到第 1 家 → 页面加载后 content script 自己续跑：投递 → 记录 → 停 15–30s → 跳下一家
4. 弹窗里能看到「已执行 X/N（成功 Y）」和「下一家」，点「停止」立即叫停

**跨页进度**：存在 `chrome.storage.local` 的 `batch` 键里（页面一导航 content script 会重新注入，只有 storage 能跨页保留状态）。

**自动停止条件**（任一命中即停整批）：
- 连续 2 家失败（页面结构变了 / 额度用完 / 补充信息没填）
- 遇到可见的验证码或风控提示
- 超过 2 分钟没有推进（URL 不匹配、页面没加载）
- 每日额度到顶

> ⚠️ **批量 ≠ 安全**。平台对连续高频操作有硬风控。**域名黑名单照旧生效**，但账号风险由使用者承担；建议每批 ≤10 家、一天不超过 2 批。确需长期投放请人工穿插。

## 八、投前筛选（M7）

批量之前先筛一遍，**不符合的直接跳过，不消耗额度、不打开页面**。

### A 方案 · 本地硬门槛（默认开启，纯本地毫秒级）

弹窗「投递筛选」面板可配：

| 配置项 | 含义 | 判断规则 |
|---|---|---|
| **城市**（可跨省多选，默认深圳） | 你愿意去的城市 | 岗位城市不在列表 → 跳过；识别不到城市但开了「严格模式」→ 跳过 |
| **每周能到岗** | 3 / 4 / 5 天 | 岗位要求 > 你能到岗 → 跳过 |
| **能连续实习** | 1 / 2 / 3 / 4 / 6 个月+ | 岗位要求 > 你能实习 → 跳过 |
| **方向**（多选） | 测试开发 / 自动化 / 接口性能 / 游戏测试 / 前端 / 全栈 / 数据 / 运营 | 岗位标题命中**未勾选**的方向 → 跳过；标题看不出再查 JD 前 1500 字 |
| **最低匹配分** | 0（不启用）/ 40 / 50 / 60 / 70 | 走后端关键词打分，低于门槛 → 跳过 |
| **用哪份简历打分** | 从简历库选 | 默认自动选标题含「测试开发」的那份 |

**城市/天数/月数从哪读**：实习僧岗位卡片上就有 `深圳 | 3天/周 | 3个月`，详情页也有 → 正则提取。
**筛选发生两次**：① 列表页抓链接时粗筛（不合条件的不进队列，省得白跳）② 详情页投递前再校验一次（列表页信息不全时以详情页为准）。

方向判断**标题优先**，避免 JD 里提到「测试」就把运营岗误判为测试岗。

### B 方案 · 后端匹配打分（可选，需网页端后端在跑）

`POST /api/match/jd { resumeId?, jdText, company?, jobTitle? }`
→ 复用 `server/lib/matcher.js` 的 `scoreResumeVsJd()`（纯关键词加权，**不调 LLM**），返回：

```json
{ "score": 63, "matched": ["node","python","测试","pytest"], "missing": ["sql","linux"], "jdKeywordCount": 12 }
```

- **不花钱、毫秒级**，适合批量前逐岗打分。
- 想更深度的对照分析用 `POST /api/match/analyze`（调 LLM，慢且花 token，仅适合手动精投）。
- **后端没跑 / 打分失败时自动放行**，不会因为后端挂了就投不出去。

- 新媒体运营 JD（小红书/抖音/文案/社群）→ **0 分**
